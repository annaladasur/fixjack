# The 30 / 90 / 180-day implementation challenge

If you saw the talk, or just found this repository: pick one repository with real bot or agent dependency traffic. Then try to move it from "bots and agents choose versions from whatever they read" to "no version is chosen from text an attacker can write".

1. **Day 0:** open an [implementation commitment](../../issues/new?template=1-commitment.yml). Say which level you are starting at and what your first action is.
2. **Week 1:** run `fixjack-baseline` and `fixjack-replay` (`docs/checklist.md`) and keep the numbers.
3. **Day 30, 90, 180:** file the matching report: [30-day](../../issues/new?template=2-report-30.yml), [90-day](../../issues/new?template=3-report-90.yml), [180-day](../../issues/new?template=4-report-180.yml).

**What you share is up to you.**
- Organization name is always optional, and numbers can be ranges.
- If you cannot post publicly, an anonymous form will be linked here before the talk.

**What happens with the reports.**
- The results, aggregated and never attributed without permission, become a public 90-day post and a 180-day follow-up. The real counts are published, including zero.
- Failures count as much as successes. A report that says "we tried Level 3, backed off, and here is why" is exactly what the next team needs.
